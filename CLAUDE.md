# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Birthday Battle is a scorekeeper for kids' birthday party games. It is a static, dependency-free browser app (plain HTML/CSS/JS, no build step, no framework, no package manager) that must keep working offline, opened straight from disk.

## Running

Open `src/index.html` in a browser (works from `file://`). There is no build, lint or test tooling, and Node is not installed on the dev machine.

To check rendering without a browser UI, use headless Edge. `--virtual-time-budget` advances timers so animations and delayed reveals finish before the screenshot:

```powershell
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --headless=new --disable-gpu --user-data-dir="<scratch>\edge" --window-size=1100,800 --virtual-time-budget=8000 --screenshot="<scratch>\shot.png" "file:///C:/.../src/index.html#/scores"
```

The README screenshots in `docs/screenshots/` were made this way at 1280×720 with a demo party of six kids. The intro opens on every page load, and opening it stops the wheel. For screen captures, inject a script after `app.js` that removes it (`intro.timers.forEach(clearTimeout); intro.el.remove(); intro = null;`), then call `render()` again.

To test a screen with data, copy `src/` to a scratch folder and inject a `<script>` before `app.js` that calls `localStorage.setItem('birthday-battle-v1', JSON.stringify({...}))`.

## Architecture

All logic lives in `src/app.js`; `src/index.html` is only a shell (`#brand`, `#nav`, `#settings-btn`, `#app`). `src/i18n.js` (loaded first) holds all interface text in German and English (`STRINGS`) and the `t(key, ...args)` helper; entries are strings or functions for numbers, names and plurals.

- **Language and settings**: every user-visible string goes through `t()`, never a literal in a template. Add new keys to both `de` and `en`. Kid and game names are user data and are never translated, including the German `DEFAULT_GAMES`. The ⚙️ button opens `openSettings()`, an `.overlay` modal with the sound switch and the language choice. Switching the language calls `setLanguage()`, then `renderShell()` (static shell text) and `render()`, so the screen behind the menu updates right away. The language is stored in localStorage under `birthday-battle-lang`, default `de`, and also sets `<html lang>`. `src/sound.js` (loaded first) defines the global `Sound` with synthesized Web Audio effects (no audio files): `click`, `tick`, `brake`, `picked`, `fanfare`, `podium`, `success`, `oh`, `turn`, `shuffle`.

- **Sounds**: every `data-action` button and nav link plays `Sound.click()` from the global click handler (except `OWN_SOUND_ACTIONS`, which play their own); screens play their moment sounds where they render (round screen `turn`, wheel ticks per slice passing the pointer, `showWinnerPop` → `fanfare`, podium reveal → `podium`, bonus → `success`/`oh`; team result plays `oh` only after the winners' fanfare). The sound switch in the settings menu stores its on/off choice in localStorage under `birthday-battle-sound`. Headless tests can't hear anything: wrap `Sound` methods to log calls instead.

- **Intro**: `showIntro()` runs on page load and when the logo (`#brand`) is clicked. It is a fixed `.intro` overlay above the app (the route underneath is untouched), timed by CSS animation delays; `Sound.intro()` follows the same timeline (drum roll, slam at 1.6 s), and `Sound.musicStart()` starts a synthesized 8-bar loop at the slam (`INTRO_MUSIC_AT_MS`) that keeps playing on the start screen until `Sound.musicStop()` fades it out when the intro is left. The music is scheduled a few hundred ms ahead from a `setInterval`; headless Edge's audio clock doesn't advance, so to test it, subclass `AudioContext` with `currentTime` from `performance.now()`. The first click/space/Enter during the animation skips to the end (`.skip`, cuts the sound); once `.ready` (after `INTRO_READY_MS`), the next one removes it and goes to `#/setup`. Avatars around the title are the kids' own (random before a party). Sounds never play before the first user gesture (`navigator.userActivation`), so the intro is silent on page load.
- **State**: one `state` object `{ kids, gameList, games, current, points, round, partyOver }`, persisted whole to `localStorage` under `birthday-battle-v1` via `saveState()` after every mutation. `gameList` is the configurable list of games (`{ id, name, active }`); `games` is the history of games played. `points` holds the 1st/2nd/3rd place values. Changing the state shape requires keeping `loadState()` compatible with existing saved data (it merges saved state over `defaultState()`, which is how older saves get `DEFAULT_GAMES`). "Start a new party" clears kids and history but keeps `gameList` and `points`.
- **Rounds**: the party is played in rounds; each round one kid (in the order kids were entered) picks the game. `state.round = { number, turn }`: `number` counts up all party, `turn` indexes `state.kids` (`turnKid()`); `turn === kids.length` means everyone has had a turn this pass, and the round screen then offers "Noch eine Runde für alle" (turn → 0) or "Party beenden" (`partyOver` → `#/final`, a podium of total points; "Weiterspielen" undoes it). `finishGame()` advances both counters and stores `pickedBy`; skipping advances only `turn`; cancelling a game advances nothing.
- **Picking a game**: new games can only be started from the round screen (`#/round`), via "Spiel aussuchen" (`#/game`, tap a game tile) or "🎲 Zufall" (`#/wheel`, the Glücksrad); `canPickGame()` redirects those screens otherwise. Both only offer active `gameList` entries. After a game, the podium and scoreboard show a single next step (`nextStepButton()`: back to the running game, "Nächste Runde", or "Endstand zeigen"); `playPath()` is where the "Spielen" nav tab leads.
- **Groups**: each list entry has `maxPlayers` (null = everyone). When fewer spots than selected kids, `beginGame()` draws random groups of near-equal size (`splitGroups`/`groupSizes`). `state.current` then holds `groups`, `groupIndex`, `done` (finished groups) and the playing group's `participants/results/medals`. Finishing a non-last group goes to `#/podium/current/<n>` (only "Nächste Gruppe"); the last group saves one history entry with `groups` (per-group results) and summed `results`. Groups are never compared with each other; history podiums show one group at a time (`#/podium/<id>/<n>` with group tabs). Old history entries without `groups` are read via `gameGroups()`.
- **Team games**: list entries have a `team` flag (`isTeam`; never combined with bonus). Team games ignore `maxPlayers`: everyone plays at once, drawn by `splitTeams()` into `current.teams = { red, blue }` (odd counts: random team gets the extra kid; "Neu mischen" re-draws). The result is `teamWinner` (`'red' | 'blue' | 'draw'`), turned into points by `teamResults()`: winners get `points[1]`, losers and draws `points[2]`. Saved games keep `teams`/`teamWinner` and are shown at `#/team/<id>` (Rot left, Blau right, `teamPanels()`). The running team game deliberately has no default button.
- **Bonus games**: `maxPlayers === 1` (`isBonus`). Only the picking kid plays; the result is "Geschafft" (1 point, or 2 via `bonusPoints()` if more than 3 points behind the second-to-last kid's total) or "Nicht geschafft" (0), then `#/bonus/<id>`.
- **Wheel weighting and sessions**: each list entry has a `played` round count. A slice's size is `base × 0.5^played` of the total (`wheelWeight`, `wheelSlices`), where base is 1 for normal games and `bonusBase()` for bonus games: 0.5 normally, 1 if the picking kid is 2+ points behind the leader, 1.5 if they are last (lowest total incl. ties and behind the leader). `finishGame()` increments `played` for the game (matched by `current.gameId`, falling back to name) and calls `normalizeRounds()`: once every *active* game has `played >= 1`, all counts drop by one, which starts a new session. Toggling or deleting games also normalizes; "Neue Party starten" resets all counts to 0. `played` is separate from the history count (`timesPlayed`), which never decreases.
- **Wheel animation** (`startWheel`): driven by `requestAnimationFrame` with a phase machine — `slow` (2 s, Stopp button locked), `ramp`, `fast` (random top speed, Stopp enabled), `stopping` (random exponential friction), `done`. The winner is the slice under the top pointer.
- **Default button + space bar**: each screen marks at most one button as its default with `data-default`, and only that button gets the filled `primary` style; alternatives are outlined. `handleSpace()` (global keydown) presses the default wherever the focus is, except in text fields/selects or while the avatar picker is open; it also suppresses the native space activation of the focused button (keyup too). Special cases: space closes the "Sieger" overlay first; on the wheel it is "Stopp" while spinning, and after the result appears it is ignored for `WHEEL_RESULT_SPACE_DELAY_MS` (1.5 s) so hammering it doesn't start the game. The Spiele screen deliberately has no default. Game result screens (final-group podium, bonus result) default to "Zum Punktestand" via `resultButtons()`, with "Nächste Runde" outlined; the scoreboard then defaults to "Nächste Runde". When adding a screen, give it a default (or decide it has none) and keep `primary` for that one button. `render()` calls `stopWheel()` so leaving the screen cancels the loop. Headless Edge doesn't run rAF under `--virtual-time-budget`; when testing, shim `requestAnimationFrame` with `setTimeout` in the test page.
- History entries store the game's name (plus `gameId` in newer saves), so deleting a list entry doesn't affect past results. Renaming one on the Spiele screen (✏️, `saveRenameGame()`: Enter or leaving the field saves, Escape cancels) also renames its history entries (matched by `gameId`, or by old name for old entries) and a running game, so `timesPlayed` keeps counting it.
- **Scores are derived, never stored**: totals are recomputed from `state.games[].results` (`totals()`), so deleting a game removes its points. `ranked()` sorts by points and gives tied kids the same rank (Olympic style: two 1sts → next is 3rd); the scoreboard, game history and podium all use it.
- **Game lifecycle**: the new-game form edits a module-level `draft` (not persisted). Starting a game moves it to `state.current` (persisted, so it survives refresh). Finishing pushes it onto `state.games` with an `id` and routes to `#/podium/<gameId>`, or straight to scores if no points were given.
- **Routing**: hash routes `#/setup` (kids), `#/games` (game list), `#/scores`, `#/round`, `#/game`, `#/wheel`, `#/podium/<gameId>/<groupNo>`, `#/bonus/<gameId>`, `#/team/<gameId>`, `#/final`. `render()` is the single entry point: it guards routes (everything except setup and games requires ≥2 kids, all named), redraws the nav, and calls one `renderX()` function. Screens are full `innerHTML` rewrites from template strings. Small in-screen updates call the specific `renderX()` directly rather than `render()`, to avoid scrolling to the top.
- **Events**: one delegated `click` listener dispatches on `data-action` attributes (plus `input` and `keydown` listeners). New buttons should add a `data-action` case, not their own listeners. Setup name inputs update state on `input` without re-rendering, to keep focus.
- **Escaping**: user text (kid and game names) must go through `esc()` when interpolated into templates.
- **Podium**: steps and ground kids start hidden; the `.reveal` class on `#stage` triggers the CSS rise and pop animations. It is added when the "Sieger <name>" overlay (`showWinnerPop`) is dismissed (3 s timeout or click).

## Design and layout

- **Primary target is a TV (1280×720 and up)**, viewed from across the room. The root `font-size` scales with the viewport (`min(1.45vw, 2.6vh)`) and everything is sized in `rem`, so the UI scales with the screen. The scoreboard, game-in-progress and podium screens (`.screen.fit`) fill the viewport height and should not scroll at 720p; the scoreboard switches to two columns above `BOARD_ONE_COLUMN_MAX` kids. Below 900px wide or in portrait, screens fall back to normal scrolling layouts, down to phone width.
- Look: a dark "game-show stage" (palette tokens on `:root` in `src/styles.css`), Bungee for display text and numbers, Baloo 2 for UI text. Both fonts are bundled in `src/fonts/` so the app works offline.
- Each kid has a `color` (from `KID_COLORS`, assigned on creation; `ensureKidColors()` backfills older saved data). Templates pass it as the CSS variable `--kid` via `kidStyle(kid)`, and it should appear wherever that kid appears.
- Watch selector specificity: `.screen.fit` sets `display: flex`, so screen-specific layout rules must be at least as specific (e.g. `.screen.scores-screen`).
- When checking rendering at small widths, note that headless Edge enforces a minimum viewport of about 492px and crops narrower screenshots.
- **UI text is German (default) and English**, written for elementary-school kids: short sentences, everyday words, no abbreviations (e.g. "Punkte", not "Pkt."). Places are written "4. Platz" in German and "4th place" in English (`t('placeN')`). Keep code, comments and identifiers in English. Avatars are emoji (no image assets).
